# 契约句式 → hypium 调用映射

## 原则：无法映射就是失败

映射失败时**抛错并回报步骤序号与原文**，绝不写成注释行。

为什么这么硬：注释行会让脚本"看起来正常"地跑完并通过 —— 该步骤根本没执行，报告却是绿的。
这是脚本级的假通过，比用例写错更危险（后者至少会失败）。

报错要让人能直接改：`第 3 步无法映射到 Hypium 调用：「随便写点什么」。请改成契约句式（…）`。

## 映射表

| 契约句式 | 生成调用 | 备注 |
|---|---|---|
| `打开应用` / `启动应用` | `self.driver.start_app(package_name="<bundle>")` + `wait(3)` | 有多个 ability 时用 `page_name="<ability>"`；**隐式启动会报 10103101** |
| `点击「X」` / `单击` / `选中` / `切换` / `勾选` / `长按` | `self.driver.touch(BY.text("X"))` + `wait(1)` | `BY.text` 是精确匹配，文本要逐字一致 |
| `输入「内容」到「控件」` | `self.driver.input_text(BY.text("控件"), "内容")` + `wait(1)` | 内容允许为空串（空值场景就是把输入置空），控件名不能空 |
| `等待 N 秒` / `等待 N 分钟` | `self.driver.wait(N)` | 秒取整，分钟换算并封顶（避免一条用例占几十分钟） |
| `上滑` / `向下滑` | `self.driver.swipe(UiParam.UP, distance=60)` / `DOWN` | 需要精确滚动时给 `start_point=(x, y)` 与 `distance` |
| `返回` / `退出` / `回退` | `self.driver.swipe_to_back()` | 返回手势，不是 `press_back` |
| `验证「X」` / `断言` / `检查` / `确认结果` / `核对` | `assert_control_text(self.driver, "X")`（来自 `aw/autotest_oracle`） | **锚定句式开头**：按钮名叫「验证」时点击它不算验证步骤 |

## 容易踩的坑（都实测过）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 按钮就叫「验证」 | 正则一旦只匹配"验证"二字，点击步骤会被当成验证步骤 | 验证句式必须锚定在**步骤开头**（`^验证\|断言\|检查\|确认结果\|核对`） |
| 单字符控件（「1」「×」） | 子串匹配会让校验形同虚设（引用「1」命中「10 秒后关闭」） | 只用全等匹配；匹配器里对短串要求两侧长度都 ≥2 |
| 无文本控件（图标按钮） | `BY.text` 找不到 | 真机 dump 里用 `#节点ID` 兜底，或用 `BY.id(...)`；**不要编文本** |
| 列表项没有自己的文本 | `BY.text` 命中不到（文本在子节点） | 用几何包含取子节点文本作为标签，或按坐标 + 校验父节点 |
| 页面没有滚动容器 | 新增的入口在屏幕外，**点了没反应、也不进布局 dump** | 要么改紧凑排版一屏放下，要么给容器加 `Scroll`；改完必须真机确认可达 |
| 点击被启动动画吃掉 | 第一次点击无效 | 点击后 dump 确认页面/文本确实变了；没变就重试一次，别判"用例失败" |
| 一条用例结果影响下一条 | 读到的上一条的结果（界面更新滞后） | 每条断言前先确认**本用例的输入特征**（如"验证对象"行）已出现 |

## 判定"步骤是否执行了"

不能只看脚本跑通。可选做法（按成本从低到高）：

1. 关键步骤后加一段 `wait`，再用判据断言该步骤的**可观察结果**；
2. hilog 关键字断言（脚本自己 `driver.shell("hilog -x")` 或 `driver.log()` 打标记）；
3. 截图对比（首跑会失败并要求确认基线，见 `oracle-mapping.md`）。

> **"脚本通过但一条断言都没被校验" = 假通过，判失败。** 别把"跑完了"当成"测过了"。
