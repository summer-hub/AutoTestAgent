# 失败归因与人工接管

dry-run 失败**必须归到三类之一**。"环境问题"不是一个归因，它只是把问题推给人。

## 三分法

| 归因 | 判据 | 处置 |
|---|---|---|
| **用例描述错** | 步骤引用的控件不在真机 dump 里；句式不可执行；前置条件缺失；判据写成了不可核对的值 | 回手工用例修正（`ohos-library-testcase-pipeline` 的 S6），再重新生成 |
| **demo 没入口** | demo 里没有能触发该场景的控件/页面；需要改参数但没有注入点 | 走 demo 改造（该技能 S5）：副本 + 最小改造 + 构建 + 真机验证，改完回来 |
| **库真有问题** | 步骤都执行了、控件都存在，但结果与声明的行为不符（异常没抛、返回错、崩溃） | **这是最有价值的产出**：按缺陷记录，附证据（报告 xml + 截图 + hilog 片段 + 复现步骤） |

判定顺序：先排除"脚本没跑到那一步"（看报告里的 Step 断点与截图），再排除"控件不存在"，
剩下的才是"库有问题"。**顺序反了会把产品缺陷归成脚本问题**，那是最亏的误判。

## 环境前置（既不是用例错，也不是库有问题）

这类失败在报告 `message` 里会给出明确错误码，**先修环境再谈用例**：

| 错误码 / 现象 | 含义 | 处置 |
|---|---|---|
| `10106102 The device screen is locked during the application launch, unlock screen failed` | 设备锁屏，且开发模式下**不会自动解锁** | **人先解锁手机**（有 PIN 的必须人工输入）；`power-shell wakeup` 只能亮屏，解不了 PIN |
| `10103101 Failed to find a matching application for implicit launch` | 隐式启动找不到应用 | `start_app` 必须给对 `package_name`，多个 ability 时用 `page_name` 显式指定 |
| `10104001 The specified ability does not exist / is not installed` | demo 没装或 bundle 名/ability 名写错 | 先构建安装（`devecocli run --module <demo>`），并核对 `bundleName`/`mainAbility` |
| `hdc` 报 Empty / Unauthorized / Offline | 设备未授权或掉线 | 重新插拔/授权；执行前用 `hdc list targets` 确认在线 |
| 报告的 `message` 里是 `ModuleNotFoundError: No module named 'hypium'` | 用了没装 hypium 的解释器 | 换装了 hypium 的解释器（本机常在 `py -3.10`） |

> 环境前置失败时，用例状态应记为**未验证**而不是"用例失败" —— 把环境问题记成用例失败，
> 会让人去改本来没问题的用例。

## 常见误判

| 现象 | 错误结论 | 正确结论 |
|---|---|---|
| `BY.text` 找不到控件 | "库的界面有问题" | 先看真机 dump：文本可能逐字不同（空格/全角）、或它在子节点/无文本控件 |
| 首跑截图判据失败 | "脚本有问题" | 设计如此：没有基线时存基线并要求人工确认，第二次跑才算数 |
| 脚本通过但什么都没断言 | "用例通过了" | **假通过**，判失败 |
| 报告里没有本次的 xml | "用例没跑" | 也可能是模块名不一致（四方一致性破了）：先查文件名/类名/`-l` 是否一致 |
| 点击后界面没变 | "用例失败" | 也可能是点击被启动动画吃掉：确认页面确实变了再判 |

## 人工接管清单（模板）

```markdown
# <库名> 自动化人工接管清单

| # | 用例号 | 为什么不能自动化 | 需要人做什么（具体动作） | 需要什么环境 | 做完怎么回流 |
|---|---|---|---|---|---|
| 1 | C-JS-009 | 需要外接数据库才有数据源 | 在设备上连测试库 → 进入「复杂校验」页 → 点「校验」 → 截图并记录结果 | 装有测试库的服务器 + 真机 | 截图与结论回填用例的「证据/关联」；若结论可复用，登记为经验条目 |
| 2 | C-JS-014 | 动画是否流畅只能人看 | 连续播放 3 分钟，观察是否卡顿/掉帧，记录主观结论 | 真机 + 插电 | 结论回填；若能定出可量化阈值（如帧率），再交给 `screenshot_diff` 自动化 |
```

「需要人做什么」必须是**可执行的动作**，不能写"人工确认一下"。

## 汇报口径

- 通过 / 失败 / 未验证 / 人工接管，四类分开统计，**不许合并**；
- 每条失败都带归因与证据链接（报告 xml 路径）；
- 明确写出**没做的事**：无设备未验证、判据缺失未生成、需要人确认的基线等。
