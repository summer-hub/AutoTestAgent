# 产出物模板

所有产出的第一原则：**每个数字都要能顺着证据查回去**。查不回去的结论不要写。

## 1. 接口清单（S1）

```markdown
# <库名> 接口清单（<版本>）

- 工程：<路径> · 入口：<library/Index.ets 或清单里的 main>
- 导出符号 <N> 个：function <a> · class <b> · enum <c> · type/interface <d>（**不计入可测分母**）
- 采集方式：<静态扫描命令/依据>

| # | 接口 | 类型 | 签名 | 参数（可选/默认） | 返回 | 声明异常 | 源码位置 | 方法 |
|---|---|---|---|---|---|---|---|---|
| 1 | Validator.validate | class | validate(instance, schema) | schema: object | 校验结果 | SchemaError | library/index.ts:120 | validate/parse/compile |
```

## 2. 覆盖矩阵（S3）

```markdown
# <库名> 覆盖矩阵（<版本>）

- 可测符号 <N>：已覆盖 <a> · 部分覆盖 <b> · 未覆盖 <c> · 不可测 <d>
- 接口覆盖率（有用例 / 可测符号）：<x>%　场景维度覆盖率：<y>%
- 未关联到接口的用例：<m> 条（不计入覆盖率）

| 接口 | 类型 | 状态 | 判定理由 | 风险 | demo 调用点 | 单测调用 | 真机页面 | 用例（正向/负向） |
|---|---|---|---|---|---|---|---|---|
| Validator.validate | class | 部分覆盖 | demo 调用 2 处，只有正向用例，缺负向 | no_negative_case | pages/SimpleValidatePage:30 | 5 处 | pages/SimpleValidatePage | C-AI-001 / — |
```

**状态**只能是：已覆盖 / 部分覆盖 / 未覆盖 / 不可测（判定见 `coverage-matrix.md`）。

## 3. 测试用例（S6）

表头必须**同时包含**：`编号`、`接口`、`场景`、`优先级`、`步骤`、`判据`（其余列可增减）——
`scripts/check_cases.py` 按这些列名定位。

```markdown
# <库名> 测试用例（<版本>）

| 编号 | 接口 | 场景 | 优先级 | 前置 | 步骤 | 预期 | 判据 | 可测性 | 证据/关联 |
|---|---|---|---|---|---|---|---|---|---|
| C-AI-001 | Validator.validate | 正向 | P0 | 已进入「简单校验」页 | 打开应用<br>点击「校验」<br>验证「校验通过」 | 界面出现「校验通过」 | control_text: 界面出现「校验通过」 | A | demo 调用点 pages/SimpleValidatePage:30 |
| C-AI-002 | Validator.validate | 空值 | P1 | 已进入「简单校验」页 | 打开应用<br>输入「」到「数据输入框」<br>点击「校验」<br>验证「数据不能为空」 | 界面出现「数据不能为空」 | control_text: 界面出现「数据不能为空」 | A | 同上 |
| C-AI-003 | Validator.validate | 大数据 | P2 | 已进入分页页 | 打开应用<br>点击「加载一万条」<br>验证「共 10000 条」 | 界面出现「共 10000 条」 | control_text: 界面出现「共 10000 条」<br>no_crash: 执行期间无崩溃 | C | 改造：PagingPage.ets 新增按钮 buildItems(10000)；devecocli build 通过；真机截图 2 张 |
```

写作要求：

- **步骤**用 `<br>` 分隔，句式必须在白名单内（见 `oracle-rules.md`）；
- **判据**非空且可核对；含糊值（正常/成功/符合预期…）会被 `check_cases.py` 拦下；
- **可测性** A/B/C/D；C 类必须在「证据/关联」里写清改造位置与验证方式；
- **控件文本**逐字来自真机 dump，不臆造。

自检：

```bash
python scripts/check_cases.py <库名>-测试用例.md
```

导出交付格式（md 是工作格式，xlsx 是交付/入库格式）：

```bash
python scripts/export_cases_xlsx.py <库名>-测试用例.md --profile generic            # 给人评审
python scripts/export_cases_xlsx.py <库名>-测试用例.md --profile autotest-platform  # 给平台导入
```

### xlsx 的两种列结构

**generic**（给人看）：与 md 表同列（编号 · 接口 · 场景 · 优先级 · 前置 · 步骤 · 预期 · 判据 · 可测性 · 证据/关联），
步骤在单元格内换行。

**autotest-platform**（给 AutoTestAgent「用例页 → 导入 Excel」）：

| 列 | 来源 | 说明 |
|---|---|---|
| 用例编号 / 用例名称 / 来源 / 前置条件 / 操作步骤 / 预期结果 / 状态 / 脚本状态 / 当前版本 / 更新时间 | 平台导入器认识的 10 列 | 操作步骤用**换行**分隔（导入器按 `\n` 拆）；状态固定写 `未执行` —— 平台没跑过它，不能谎报 |
| 判据 / 可测性 / 优先级 / 关联接口 / 验证状态 / 证据 | 附加列 | 平台导入时会**忽略**，但人打开文件能看到断言契约与真机验证结论 |

导出时还会自动生成第二张工作表「说明」：来源文件、生成时间、用例总数、按场景/按可测性分布、
已真机验证通过条数、生成命令，以及"平台会丢判据列"的提醒 —— 便于日后追溯这份表怎么来的。

> 交付件里 **`状态`** 与 **`验证状态`** 必须分清：前者是平台执行状态（未执行），
> 后者是本技能的真机验证结论（已真机验证通过／未验证草案）。把两者混为一谈就是虚报。

## 4. 人工接管清单（S8，D 类）

```markdown
# <库名> 人工接管清单

| # | 用例号/接口 | 为什么机器测不了 | 需要人做什么（具体动作） | 需要什么环境 | 做完怎么回流 |
|---|---|---|---|---|---|
| 1 | C-AI-009 / Validator.validate | 需要外部数据库才有数据源 | 在设备上连测试库 → 进入「复杂校验」页 → 点「校验」 → 截图 | 一台装有测试库的服务器 + 真机 | 把截图与结论回填到用例的「证据/关联」，并把结论登记为经验条目 |
```

「需要人做什么」必须是一个**可执行的动作**，不能写"人工确认一下"。

## 5. 改造清单（S8，C 类）

```markdown
# <库名> demo 改造清单

| # | 用例号 | 改什么 | 文件 | before → after | 验证方式 | 验证结果 | 回退方式 |
|---|---|---|---|---|---|---|---|
| 1 | C-AI-003 | 新增大数据入口按钮 | entry/.../PagingPage.ets | 无 → 新增 buildItems(10000) 按钮 | devecocli build + 真机点击 + 截图 | 通过（截图 2 张） | 删除该按钮与对应方法 |
```

## 6. 汇总报告（S8）

```markdown
# <库名> 测试用例产出报告

## 结论摘要
- 对外可测接口 <N> 个，已覆盖 <a>，部分 <b>，未覆盖 <c>，不可测 <d>（分母口径：排除 type/interface）
- 产出用例 <M> 条：正向 <x> · 空值 <y> · 边界异常 <z> · 大数据 <w>
- 判据覆盖率 <p>%（每条用例至少一条可机器校验判据）；假通过 <q> 条

## 覆盖情况（逐接口可核对）
<引用覆盖矩阵文件与行数>

## 未覆盖清单
| 接口 | 缺什么 | 为什么没覆盖 | 补它需要什么 |

## 人工接管
<引用人工接管清单>

## demo 改造
<引用改造清单>

## 本次没做的事（如实写）
- <例：未在真机上验证（无在线设备）>
- <例：需求文档缺失，本次按库全量接口为轴>
```

最后两节最重要：**"未覆盖"和"没做的事"必须显式写出来**。只报喜的报告等于没有报告。
