# 判据（oracle）规则（S6）

**一条用例没有可机器校验的判据，就只是一段散文。** 它跑出来"通过"也证明不了任何事 —— 这叫假通过。

## 可用的判据类型

| 类型 | 字段 | 适用 | 例 |
|---|---|---|---|
| `control_text` | `{control, expect: appear\|disappear}` | 界面出现/消失某个控件文本 | 校验失败后出现「格式错误」 |
| `text_value` | `{control, op: contains\|equals\|matches, value}` | 控件文本等于/包含/正则匹配 | 结果区包含 `true` |
| `state_flag` | `{control, state: true\|false}` | 勾选/开关状态 | 开关变为选中 |
| `hilog_keyword` | `{keyword}` | 日志里出现关键字（含错误码） | 出现 `jsonschema` 或错误码 |
| `no_crash` | `{}` | 执行期间无 E 级日志、被测应用仍在前台 | 边界输入后不崩 |
| `screenshot_diff` | `{threshold}` | 截图像素差异在阈值内 | 动画/渲染类场景 |
| `script_assert` | `{expr}` | 脚本内非平凡断言 | 断言返回值等于某常量 |

## 必须禁止的写法

| 禁止 | 例子 | 为什么 |
|---|---|---|
| 含糊期望值 | 正常、成功、功能正常、符合预期、可用、没问题、OK | 无法核对，等于没写判据 |
| 恒真断言 | `assert true`；或光秃秃一个 `true` / `1` / `pass` | Python 里表达式语句本身没效果，脚本会"安然通过" |
| 指向笼统控件 | 控件名写"正常"、"结果"、"提示" | 定位不到，判据无法执行 |
| 只断言"界面还在" | 点完之后只断言首页仍在 | 证明不了接口行为，属于弱判据 |
| 判据与场景无关 | 空值场景的判据是"没有崩溃" | 空值场景应断言**错误提示文本或错误码** |

**判据要证明接口行为，不只是证明没崩。** 负向场景的判据优先选：
声明的异常类型对应的错误码/错误文案、界面上的错误提示文本、日志里的错误关键字。

## 句式与控件引用

步骤必须落在可执行句式白名单内（越界句式无法转成自动化脚本）：

```
打开应用 / 点击「X」 / 输入「文本」到「控件」 / 等待 N 秒 / 上滑 / 下滑 / 返回 / 验证「X」
```

- 步骤里引用的控件文本**必须逐字来自真机 dump**（`devecocli ui layout`），不能凭空写；
- **单字符控件**（如「1」「×」）只能用全等匹配；用子串匹配会让校验形同虚设
  （引用「1」会命中「10 秒后关闭」）；
- **点了一个叫「验证」的按钮，不等于做了一次验证**：验证步骤的识别要锚定句式开头
  （`^验证|断言|检查|确认结果|核对`），不能只看到"验证"两个字就算。

## 假通过与弱通过

| 结果 | 判定 | 说明 |
|---|---|---|
| 脚本通过，但**一个判据都没被校验** | **假通过**（必须判失败） | 最常见也最危险的形态 |
| 脚本通过，判据为空数组 | **假通过** | 断言为空的用例根本不该入库 |
| 脚本通过，判据是不可核对的含糊值 | **假通过** | 同上 |
| 脚本通过，判据有效，但步骤里**没有验证动作** | 弱通过 | 提示改进：建议补一步验证 |
| 脚本通过，验证步骤被**跳过** | 弱通过 | 不算"已验证" |
| 脚本失败 | 不是假通过 | 失败本身是有效信号 |

入库/交付前的门禁：

1. **判据覆盖率 100%**：每条用例至少一条可机器校验判据；
2. **假通过 0**：按上表逐条自查；
3. 判据不合规的用例**直接拦下**，不是打个标记放过去。
