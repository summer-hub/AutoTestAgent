# ohos-demo-coverage-analyzer

为已 ohos 化的三方库生成 Demo 场景覆盖率分析报告的 AI Skill。

## 功能说明

本 Skill 对比 Demo 场景文档与现有工程 entry 目录中的 Demo 代码，自动生成 Demo 场景覆盖率分析报告，输出为 `{库名}Demo场景覆盖率报告.md` 文档。

报告量化评估以下内容：
- **场景覆盖状态**：完全覆盖 / 部分覆盖 / 未覆盖，每个场景有明确判定依据
- **接口覆盖率**：场景涉及的接口在 Demo 代码中的调用情况
- **覆盖差距分析**：部分覆盖和未覆盖场景的具体差距及补充建议
- **补充优先级**：基于场景重要性给出的开发优先级建议

### 核心能力

- 📄 **场景文档解析**：读取并解析由 `ohos-demo-scenario-generator` 生成的 Demo 场景文档
- 🔍 **代码扫描分析**：扫描 entry 目录下所有 Demo 相关文件，提取接口调用和交互逻辑
- 📊 **四维匹配分析**：从接口覆盖、交互路径、体验指标、设计关注点四个维度进行场景匹配
- 📋 **覆盖率报告生成**：生成包含覆盖统计、差距分析、补充建议的完整报告
- 🎯 **优先级评估**：按核心功能缺失、功能不完整、增强体验三级给出补充建议

## 使用场景

- 评估已有 Demo 代码对规划场景的覆盖程度
- 发现 Demo 覆盖盲区，指导 Demo 代码补充优先级
- 作为 Demo 开发完成后的质量验收依据
- 配合 `ohos-demo-scenario-generator` 技能完成"场景规划 → 代码实现 → 覆盖率分析"完整闭环

## 推荐工作流

```
Step 1：使用 ohos-demo-scenario-generator 技能生成 Demo 场景文档
Step 2：使用 ohos-demo-code-generator 技能生成 Demo 示例代码
Step 3：使用本技能对比场景文档与 Demo 代码，生成覆盖率分析报告
Step 4（可选）：根据报告中的补充建议，迭代完善 Demo 代码
```

## 输入要求

- **必需**：Demo 场景文档路径（由 `ohos-demo-scenario-generator` 生成的 `{库名}Demo场景.md`）
- **必需**：工程 entry 目录路径（鸿蒙工程中包含 Demo 代码的 entry 模块目录）
- **可选**：输出目录路径（默认为 Demo 场景文档所在目录）

## 输出说明

- **文件名**：`{库名}Demo场景覆盖率报告.md`
- **输出位置**：Demo 场景文档所在目录（或用户指定目录）
- **文档结构**：概述 → 场景覆盖详情 → 未覆盖场景详细分析 → 功能模块覆盖统计 → Demo 代码文件清单 → 补充开发优先级建议

```markdown
- 🔶 部分覆盖：3 个（25%）
- ❌ 未覆盖：4 个（33%）

## 场景覆盖详情

### 正向场景覆盖
| 场景编号 | 场景名称 | 覆盖状态 | 接口覆盖率 | 匹配文件 | 差距说明 |
|---------|---------|---------|-----------|---------|---------|
| S01 | 基础 GET 请求 | ✅ | 3/3 (100%) | Index.ets | — |
| S03 | 创建自定义实例 | 🔶 | 1/2 (50%) | Index.ets | 缺少 headers 配置 |

## 补充开发优先级建议

### 🔴 高优先级
1. **S05 请求拦截器设置** — 核心功能，完全未覆盖
```
