# AutoTest 平台 · 核心业务逻辑提取（供新架构重写）

> 来源：对 `autotest/`（后端 ~25k 行 TypeScript + React SPA + CLI/MCP 规格）的只读分析。
> 本文只保留**业务逻辑**：领域模型、状态机、主流程、规则与不变量、失败语义。
> 代码组织方式（Cordis 插件 / DSH 宿主 / tarball 分发等）一律不列入，重写时自由取舍。

---

## 0. 一句话定位与核心对象

**把「一个鸿蒙三方库」变成「一次可复现的测试运行」。**

核心对象的形式化定义：

```
一次可复现的测试运行 = 代码 × 环境画像 × 资源集 × 用例 × 设备
                        │        │          │        │      │
                    libraries  env_profiles test_res  cases devices
                    (+克隆)    (+steps)    _resources       (hdc)
```

这个项目约 90% 的工程量原本在链尾（用例→矩阵→脚本→执行→归因），后来补齐了链头
（克隆→依赖→构建→装包→资源→环境）。**两条链都要保留**，这是它区别于"普通用例管理系统"的根本。

## 2. 五条核心业务流程

### 2.1 流程 A：用例生产链路（P1→P11 分层，规则层全部纯函数）

**核心思想：规则层决定"该不该有这条用例、判据够不够硬"，LLM 只负责把已定好的计划写成文字。**

```
P2 apiExtract      已克隆仓库 → api_symbols + demo_assets + 《接口清单.md》
P1 uiExplorer      在线真机 BFS → pages/ops/coverage/warnings（explore/<lib>/*.json）
P3 coverageMatrix  symbols+demo+遍历证据+用例 → 覆盖矩阵（先删后插）
P11 caseLink       cases 快照 + symbols + 遍历 → case_symbol_links（显式>页面>名称 三级推断）
P4 casePlan        以上全部事实 → LibraryPlan（适用性+数量模型+触发器展开，无 LLM）
   用例生产(executor) 计划切片/遍历页面/用户 prompt → LLM 生成 → 控件真伪校验 → 定向修复
                       → 自审 → 入库（cases.status=待确认 + V1 快照）
P5 testability     case+symbol+demo+遍历 → A/B/C/D 判定 + 补丁草案
P8 scriptBinding   case+oracle → hypium/testcases/<lib>/<lib>_<caseNo>.py + .json + oracle 适配层
   执行(hypiumRunner) python main.py <module> → 解析 xdevice 报告
   判定(oracle)      oracles+执行事实 → QualityReport（断言覆盖率、假通过检测）
```

**用例数据契约**（重写时的字段基线）：
`library_id, case_no, name, source, precondition, steps[], expected, status, script_status,
dts_url, current_version, api_symbol_id, scenario_kind, priority, testability, testability_reason,
demo_patch_json, oracle_json, symptom`。

**步骤句式契约**（与脚本生成一一对应，逐字）：
`打开应用` / `点击「X」` / `输入「内容」到「X」` / `等待 N 秒` / `上滑|下滑` / `返回` / `验证「X」`
- 校验只查点击/输入类引用的控件；二段式输入取后半段为控件；
- 控件文本必须**在该页真机遍历控件清单里**（全等=强证据；子串需两侧≥2字）；
- 违规先回灌 LLM 修一次，复检不过才丢弃；
- `isVerifyStep` 只按**句首**判断（按钮名叫"验证"不算）。

**oracle 七类判据**（可机器核验是入库的硬门槛）：
`control_text` / `text_value` / `hilog_keyword` / `state_flag` / `no_crash` / `screenshot_diff` / `script_assert`
- 非空数组、类型必须在七类内、必填字段齐全；
- `VAGUE_VALUES` 黑名单（"正常/成功/符合预期…）一律拒收；
- `assert true` 与裸常量判恒真拒收；机器字面量 true/false/ok 放行（界面真会显示）；
- 空 oracle 或不可核验 = **不允许入库**。

**来源分类**：AI 生成（`C-AI-xxx`）/ Excel 导入（`C-IMP-xxxx`）/ 问题单跟踪（靠 `issue_tickets.case_id + cases.symptom`，不靠 source 列）。
草稿与正式的唯一分界是**有无可机器校验的判据**（`isDraftCase`），不看来源和版本号。

**apiExtract（1221 行）算法要点**：自研源码扫描状态机（注释/字符串/模板/正则含字符类）产 codeOnly 与 commentFree 两份**等长**文本——不先剔除注释字符串，后续匹配会错位且静默变少；入口取 `oh-package.json5` 的 main/types；逐层解析 export 形态并沿相对 spec BFS（≤60 文件）；按名找定义体（有 prototype 方法的是类不是函数）；`detail_level` 三档 full/decl-only/name-only，**拿不到定义体就诚实记录 name-only，不编签名**。

**hypiumGen（765 行）要点**：单工程 + 库命名空间；模块名=文件名=Python 类名=`-l` 参数=报告模块名，四方统一由 `<libSlug>_<caseNoSlug>` 产出，改用例标题不改文件名；步骤→driver 调用是**确定性映射不经 LLM**（点击→`touch(BY.text(...))`、输入→`input_text`、等待→`wait`、验证→`assert_control_text`），**映射不上直接抛 UnmappedStepError，不落注释行**；七类 oracle 统一落到唯一适配点 `aw/autotest_oracle.py`；`writeCaseScript` 前查 `scriptHasAssertion`，无断言抛 `NoAssertionError` 拒绝绑定。

**testability 四类判定（确定性，覆盖 100% 用例，不留空）**：
- **A** demo 有调用 + 页面有控件 + 正向且控件全部真实存在 → 直接生成脚本
- **B** 负向/大数据但页面有可注入数据点（@State 字面量）→ 产参数替换补丁
- **C** demo 无调用 / 页面无控件 / 引用不存在的控件 / 无可注入点 → 需改代码
- **D** 命中明确外部信号（数据库、网络、蓝牙、相机、第二台设备、人工判定、物理操作、≥10 分钟长时）→ 人工队列（**唯一允许拒测的出口，必须写信号词**）
- 补丁纪律：只在独立副本上应用；`before` 必须在文件中**恰好出现一次**（0=源码已变、多次=位置不唯一，都拒绝）；写 manifest 保证精确回退；目标路径越界即拒。

**uiExplorer / uiModel（真机遍历）要点**：可交互判定**只看 dump 标志不看文本**（否则 68/69 个无文本图标按钮全丢）；去重键=身份+100px 坐标桶+视口；页面签名默认不含坐标；预算四维（页数/时长/单页点击/单页滑动）任一耗尽即停并记原因。产出 `traversalEvidence`（routes/allControls/breadcrumbToRoute）**同时被 oracle、用例、覆盖矩阵、可测性复用**——"真机上到底有没有这个控件"只有这一处事实源。

**coverageMatrix 判定顺序**（顺序刻意）：blocked（类型符号/已废弃）→ not_covered（demo 无调用且无用例）→ partial（只有单测/只有正向/有用例无调用）→ **covered 必须同时有 demo 正向调用和负向用例**。覆盖率分母排除 blocked。

**其余四件**：
- **dryRun**：用例在设备上逐步真跑，失败点抓"当时界面实际可见控件"+hilog 产 `failureBrief` 回灌 LLM 重写（明令禁止引用不存在的控件）；连续失败 2 步后跳过（界面已偏离，后续失败不可信）。
- **demoScenarios**：场景维度覆盖度，md 是唯一事实源，DB 只是快照；结论与接口覆盖率矛盾一律进 warnings 不静默。
- **scriptBinding**：四态优先级 broken > manual > stale > fresh；哈希不符=人改过，**不自动覆盖**；用例升版自动标 stale。
- **agentBinding**：阶段即接口，9 个 stage 各有输入/输出 Schema；解析优先级 按库>全局>内置；四种实现（builtin/prompt/skill/external）；每次运行把生效绑定写进轨迹，可回答"这条用例是哪个 agent 生成的"。

### 2.2 流程 B：任务执行引擎（9 类任务）

| type | 语义 | 关键产出 |
|---|---|---|
| `pull_repo` / `update_repo` | 真实 git clone/pull（URL 时自动建库并回写 library_id） | 仓库摘要；update 附加变更文件明细 |
| `write_cases` | 解析工程→命中页面源码+真机遍历控件→LLM 生成→自审→入库→绑脚本 | cases + Hypium 脚本 |
| `explore_cases` | 真机 BFS 遍历→分片(map-reduce,并发3)生成→guardrail→自审→入库→dry-run 闭环 | 遍历报告+用例+脚本 |
| `update_cases` | 按仓库版本变更（近 20 个变更文件）增量更新用例 | version+1+新快照 |
| `to_script` | 未绑定用例→**确定性模板**生成脚本（不耗 token） | 脚本+绑定；逐条记失败原因 |
| `matrix_cases` | 覆盖矩阵+适用性**纯函数**算好"该生成什么"，LLM 只写出来 | 用例+覆盖率前后对比 |
| `integrate_cases` | 初版草稿→正式用例：关联接口→补 oracle+对齐真机控件→补缺→复算矩阵 | 正式用例 |
| `analyze_issue` | 工单根因定位+自测试验证 | 工单 root_caused→verifying |

**状态机与三把锁**（这是执行引擎的真正内核，务必保留）：
1. **原子占位**：`UPDATE tasks SET status='running' WHERE id=? AND status<>'running'`，changes=0 则跳过——防重试/并发/lane 重复入队跑两份；
2. **终态守卫**：所有执行中写回都带 `AND status='running'`，取消后迟到的结果不覆盖终态；
3. **取消（lane）**：laneKey=library_id，**同库串行、跨库并行**，进程内 FIFO；排队中→直接出队；运行中→AbortController + AsyncLocalStorage 中断在途 hdc 子进程。

**轨迹**：`task_events` append-only，seq 由 `INSERT..SELECT MAX(seq)+1` 原子分配 + 唯一键兜底；`tasks.trace` 只是可重建的物化快照。

**质量闭环三层**（确定性校验先于 LLM 自审）：
`normalizeDraftCases` → `validateDraftsAgainstPages`（控件引用真实性，违规回灌修复一次）→ `validateOracles`（硬门槛）→ `reviewAndRefine`（自审，**增量合并不整表替换**，教训沉淀 agent-memory 实现自我进化）。

### 2.3 流程 C：执行计划与真机执行

**五种模式**：immediate（创建即跑）/ scheduled（node-cron，删计划先注销防空转）/ single / batch / full。
后三者是**抽样策略**：single 截 200、batch 截 30、full 每 750 条抽 1 再截 60（`exec.planSample*` 可配）。

**三种失败策略** `fail_policy`：continue（默认）/ retry_twice（失败重跑至多 2 次）/ abort_library（该库一失败，剩余用例记 skipped"整库失败中止"）。

**"无在线真机 → 计划直接 failed 并写明原因，绝不回退模拟"** 的三处代码落点（重写必须保留）：
1. `hdcAvailable()` 失败 → `failPlan('真机未连接：未检测到 hdc…')`；
2. `hdc list targets` 为空 → `failPlan('hdc list targets 为空…')`；
3. `detectPython()` 无带 hypium 的解释器 → `failPlan(describePythonProbe(...))`（写明探测过哪些解释器、哪个缺 hypium）。
三条都是 failPlan 后 return，**无任何模拟分支**。

**真机执行链路（每步判据）**：
1. 识别设备：周期 `hdc list targets` → `hdc -t <serial> shell param get const.product.model/software.version` → upsert devices；历史假设备（HDC- 前缀+型号双重匹配）清理；
2. 装包：`hdc install -r`，**成功判据=输出含 "Successfully install"**（部分 hdc 版本失败也返回 0，退出码不可信）；
3. 拉起应用：`aa start -b <bundle> -a <ability>`，**必须显式 -a**（隐式启动真机返回 10103101）；ability 来自库配置 / `bm dump -n` 解析 / 模糊匹配并过滤系统包；
4. Hypium 执行：`detectPython` 判据是 `import hypium` 成功而非 python 存在；`python main.py <module>`（xdevice `run -l <module> -ta agent_mode:bin;screenshot:true`，10 分钟超时）；
5. 结果回收：只认本次新生成的 reports 时间戳目录（**防拿旧结果假通过**）；必须**精确匹配 classname/name=module**（对不上=failed，禁止用别模块冒充）；`unavailable=1`→failed；无报告→failed。

**运行态自愈**：启动时把上次残留的 running（任务/计划）与遗留 pending 全部置 failed（否则前端永久转圈且不给重试入口）；每 5 分钟按 `updated_at < now-30min` 清僵死（执行体每步刷 updated_at 避免误杀）。

### 2.4 流程 D：环境与资源纵轴（链头，L0-L3）

**四级分层（成本是设计核心：AI 的单位成本从"每库"降到"每类+每异常"）**：

| 级 | 输入 | 输出 | 成本 |
|---|---|---|---|
| L0 静态画像 | RawRepoScan（files/readme/oh-package/build-profile/gitmodules/二进制/样本资源） | library_facts：kind/kindReason/confidence、buildTarget（有 entry/app 模块→hap，有 modules→har）、hasBinary+abi、hasDemo、entryFile、resourceCandidates(7 类启发式)、readmeIntel(≤60 条中英) | **零 LLM** |
| L1 预设匹配 | facts.kind + `presets/<kind>/preset.json` | env_profiles draft（source=preset） | **零 LLM** |
| L2 LLM 增量 | **只跑** needs_llm=1 的库（kind unknown / buildTarget unknown / 含 so: 二进制 / confidence<60 / README 有外部前置） | env_profiles draft（ai_draft）+ 不确定项入 human_queue | 花 token，受预算闸门 |
| L3 人工确认 | human_queue / draft 画像 | status=confirmed + confirmed_by/at | 人 |

类别判定规则**有序**（animation→network→storage→codec→crypto→ui_component 放最后，避免泛信号误吞）：强信号→85（叠加弱信号 95）；无强信号但 ≥2 个**不同**弱信号→55；否则 unknown。

**脚本资产契约（14 个，契约即数据，七项齐全）**：
契约七项 = 输入 / 输出 / 适用条件 / 失败分类 / 幂等 / 超时 / 审批等级。

| 脚本 | 关键判据（重写必须逐条保留） |
|---|---|
| `ohpm_install` | **oh_modules 目录必须真存在** |
| `build_manifest` | manifest JSON 落盘 + bundleName 读得到 |
| `build_har` / `build_hap` | 产物必须 stat 到；**退出码 0 但无产物 = artifact_not_found** |
| `hdc_install` | installLog 含 "Successfully install" |
| `submodule_sync` | 无 .gitmodules 是**正常情况**，成功跳过而非失败 |
| `binary_dep_fetch` | 缓存→下载→现编三源统一；ABI 白名单防目录穿越 |
| `smoke_check` | 四级校验，成功判据显式 `SMOKE_OK` |
| `gen_ca` | SAN 必填（现代客户端不认 CN）；幂等复用未临期证书 |
| `mock_server_up/stop` | 后台常驻 + pid 文件；空 fixture 目录是失败 |
| `xts_scaffold/run/report` | **只做 scaffold + run + 解析，刻意不生成用例** |

加载期校验（`validateContract`）：id 小写蛇形、entry 相对无 `..`、version x.y.z、参数名唯一、**设了 timeout_sec 就必须把 timeout 纳入 failure_taxonomy**（否则超时归 unknown）、timeout∈(0,7200]。`contractFingerprint`=sha256 前 32 位用于漂移检测。DB 覆盖优先于内置，`enabled=0` 软禁用。

**runner 机制（串联的唯一方式，禁止固化绝对路径）**：
- 占位符 `{{repoDir}}`/`{{hapPath}}` 运行期递归替换；空串视为未提供；残留占位符报错，**绝不把 `{{xxx}}` 原文传给脚本**；
- 上游标量串联：脚本向 stdout 打 `UPPER_SNAKE=value` **整行**，归一成小驼峰（`HAP_PATH→hapPath`），只认整行 KEY=value 避免误吞日志；下游参数写 `{{hapPath}}` 即引用；
- 产物校验：契约 `type:'path'` 的输出逐一 stat（路径取自入参**或**标量输出两侧合并——只查入参会令 artifact_not_found 形同虚设），exists/size/sha256 落 artifacts_json；`ok = exitCode===0 && 无缺失 path 产物`；
- **缓存复用含 failed**：`fingerprint=sha256(toolchain+steps+commit)` 前 32 位；同指纹的 passed **或 failed** 都复用（环境失败在工具链不变时每次都会同样失败，不复用=反复白等）——这是"二次执行耗时<20%"的实现；逃生阀是 `allowCache=false` 或改指纹；
- 步骤级 `required=0` 失败不中断；前置必填失败 → 后续必填步记 skipped 且**必须落库**；
- 跨平台入口 `.ps1`/`.sh` 成对，参数前缀 **ps1 用 `-name`、sh 用 `--kebab-name`**，`shell:false` 数组传参防注入。

**失败分类（11 类，优先级固定）**：
`network / permission / toolchain_missing / sdk_version_conflict / compile_error / missing_dep /
device_offline / artifact_not_found / timeout / cancelled / unknown`

判定优先级：**取消 > 超时 > 退出码 > 信号文本**
1. signal 中止 → cancelled（取消不是脚本的错）
2. timedOut 或 exitCode==3 → timeout
3. exitCode==2 → toolchain_missing（脚本没来得及打印 command not found）
4. SIGNALS 有序匹配：toolchain_missing（**必须最前**，否则被编译规则吃掉）→ network → permission → device_offline → sdk_version_conflict → missing_dep（**缺文件归环境不完整，先于 compile_error**）→ compile_error → artifact_not_found
5. exitCode==1 无命中 → unknown（**"码表该扩了"的信号，不是 bug**）

退出码归一：`OK=0 / BIZ_FAILED=1 / ENV_MISSING=2 / TIMEOUT=3 / CANCELLED=4`；无退出码→ENV_MISSING。
**`inTaxonomy=false` 的含义**：归类结果不在该脚本契约声明的 failure_taxonomy 里 = 契约该扩了。

**survey pipeline（348 库全量）**：固定 worker 池（默认并发 4）+ 共享游标，**不能 Promise.all 分批**；
断点续跑（resume 时 status∈{done,needs_llm} 且 last_commit 未变 → skipped）；
单库失败隔离（只记该库 failure_kind，`repo_missing` 是常见预期状态而非错误）；
可取消（signal 在库间隙检查）；可观测（每步自增 done/failed/skipped/needs_llm）。
**验收三指标**：画像完整率 / 预设命中率（目标 ≥70%）/ L2 触发率（应随批次下降）。

**resourcekit（三类来源，全部登记，绝不现场编）**：
- `repo_scan`：clone 后扫 demo/example 等目录，按 schema 特征识别，**带理由登记**；
- `canonical`：上游官方样本，**固化 URL + 版本**；
- `synthesized`：程序合成，登记 content + generator + intent。
`resource_id` 是稳定主键（重复登记只 UPDATE 内容哈希与版本）；`reuse_count` 度量真实价值；证书类带 expires_at，30 天临期检出。

animation_json 六变体 ↔ 测试意图（schema 校验刻意只校验最小容器集）：
`minimal` 基本解析链路 / `empty-layers` 空值场景（合法输入）/ `huge-layers` 大数据 200 图层 /
`nested-precomp` 递归解析 / `malformed` 畸形 JSON（必须走 error 回调）/ `bad-encoding` 非法 UTF-8+NUL。
校验只查七必备键 `v/fr/ip/op/w/h/layers`、fr>0、w>0、h>0、op≥ip、layers 是数组（**空数组合法**），
**故意不校验 layers 内部**（那是库的实现细节）。故 malformed 校验失败是**预期**：仍登记（validated=0 + valid_problems 记原因），不阻塞、不静默丢弃。

### 2.5 流程 E：问题归因闭环 + 知识沉淀

```
人在「测试用例」页填「问题现象」(cases.symptom)
  → 建 issue_tickets(status=pending)
  → 入 analyze_issue 任务
  → AI 克隆工程、组装上下文（用例/oracle/页面源码/真机遍历 dump/接口签名/执行日志/README）
  → 定位根因并给出**可回查的证据**（file:line）
  → 有真机则自测试复现；无真机/无步骤/无判据/复现未过 → 一律 failed 并写明原因（绝不回退模拟）
  → status=verifying 待人工验收
  → 验收通过 → 沉淀为知识条目（下次同类问题可召回）
  → 驳回 → 也留理由供反查
```

知识库：正文在 .md（唯一事实源），DB 是索引；召回带"为什么命中"的可解释理由；
**无证据拒绝确认**。agent-memory：自审教训沉淀，实现自我进化。

**与既有"执行归因"的分工**：那个分析**执行失败**（输入是失败轨迹）；本功能分析**人的疑问**（输入是用例+人写的现象）。

## 3. 业务规则与不变量（重写检查清单）

这些是跨全站的纪律，是这个项目"结果可信"的根基：

### 反假通过（最重要）
1. **oracle 硬门槛**：无机器可校验判据的用例不允许入库；`assert true`/裸常量/模糊值黑名单拒收。
2. **假通过检测**：passed 但 oraclesChecked=0 → 假通过；无显式验证步骤 → 弱通过。
3. **no_crash 必须三重限定**：package_name + PID + 时间窗。
4. **hilog 只读本次执行期间**；截图基线未确认不算通过。
5. **xdevice 报告必须精确匹配模块名**，不许拿别的用例顶替。
6. **断言覆盖率 100% 与假通过 0 是发布硬门槛**（`/libraries/:id/quality`）。

### 不灌虚假数据
7. 拿不到定义体 → 记 name-only 并说明不可信，**不编签名**。
8. 遍历找不到控件 → 返回空数组，**不编造**。
9. 报告数字必须从实际计划数出来（纯函数化），问题根因绝不编 file:line。
10. LLM 不可用 → **直接失败，不降级到规则兜底**。

### 无真机不回退模拟
11. 启动失败/前台是系统界面/应用未起来 → 记 warning 并说明"结果不可信"。
12. 没有装了 hypium 的解释器 → 返回 null 如实失败。
13. 计划/任务三条 failPlan 前置校验见 §2.3，无任何模拟分支。

### 控件与步骤真实性
14. 控件文本逐字来自真机遍历清单（全等=强证据，子串需两侧≥2字）。
15. 步骤→driver 映射不上 → 抛错，不落注释行。

### 产物必须真存在
16. 退出码 0 但缺产物 = 一等公民失败（artifact_not_found）。

### 人工不被冲掉
17. manual 关联/绑定不被自动覆盖；先删后插的快照保留 manual。
18. xlsx→db **单向**，只 UPDATE `repo_url/repo_subpath` 两列，绝不覆盖 Agent 维护的事实（package_name/main_ability/last_commit/status…）。
19. demo 补丁只在独立副本上改，用户仓库只读；骨架文件只补缺。
20. 库里有、表里没有的库**只报告不删除**（删库会级联删用例与执行历史）。

### 其它
21. **一次性审批令牌**：approve 建 approved+未消费记录；重试同一 (kind,target) 找到即消费放行；已有 pending 同 target 幂等复用不堆单；否则建 pending 抛 409。
22. **掩码回传=不改动**：settings 的密钥掩码原样回传被识别为"不改动"，不会覆盖真实凭据。
23. **缓存失效时序**：`invalidateCaseCaches()` 必须在写库成功后调用（写在之前会让并发读把旧值回填造成 TTL 脏读）。
24. **归档显式列清单**（不用 SELECT *），防两表列漂移静默失效。
25. **目录穿越防线**：子路径先 URL 解码再逐段剔除 `.`/`..`；文件浏览 API 双重校验。
26. **SQLite `LIMIT -1` = 无限制**是全表返回陷阱；整数查询参数必须同时给上下限。

## 4. LLM 编排规则

- **模型来源**：models 表（OpenAI 兼容协议，base_url 安全校验：仅 http/https，拒 169.254.0.0/16、metadata.google.internal、[fd00:ec2::254]；环回与本网段放行给本机 ollama）；DSH 插件形态复用宿主模型。
- **候选与换模型**：首选 → 其余候选 → 不足 3 个绕回首选；重试改为**跨模型切换**而非同模型重试。
- **JSON 容错**：两次严格 JSON 重试（llmJson），从模型回复里抠 JSON；两次都失败 → 任务 failed。
- **token 记账**：每次调用（成功/失败都带 tokens）记 `agent_events`；spanId/parentId 串父子，traceId 全链观测。
- **单任务预算闸门**：`agent.maxTokensPerTask`（默认 300000，0=不限制），超限即中止该任务后续模型调用。
- **限流**：每分钟上限（`exec.llmRatePerMin` 默认 10）超限 429；配 Redis 用 `INCR` 做**跨节点共享**固定窗口，未配退回进程内滑动窗口；模型连通性测试也计入。
- **L2 必须透传 taskId**，否则预算闸门完全失效。
- **Prompt 纪律**（L2 场景）：scriptId 只能取清单、projectDir 必须填 `{{repoDir}}`、判不准填 unknown、不确定写 uncertainties；落库前逐步校验存在且 enabled。

## 5. 横切能力清单（按需取舍）

### 5.1 认证 + RBAC
API Key 明文 `at_<43 位 base58>`，**库内只存 SHA-256**，明文仅创建时展示一次；
三角色 admin(3) > operator(2) > viewer(1)，默认 GET=viewer、写=operator，settings/models/auth-keys 显式 admin；
**回环豁免**（默认开）：127.0.0.1 视为 admin（桌面端 WebView 免 Key）；认证默认关闭。

### 5.2 凭据加密
AES-256-GCM 信封，密文格式 `enc:v1:<iv>:<tag>:<ct>`（v1 是算法轮换锚点）；
主密钥：`AUTOTEST_MASTER_KEY` > 数据目录 `.master-key`（首次生成 32 随机字节）；
Windows 用 icacls 收敛 ACL（POSIX mode 在 NTFS 无效）；**懒迁移**不阻塞启动；出参走掩码。

### 5.3 事件与实时通道
`task_events` append-only，seq 原子分配 + 唯一键兜底，`tasks.trace` 是可重建快照；
WS：`/ws?token=<key>`（浏览器不支持自定义头）；频道仅 `global` 与 `task:<id>`；
同一事件命中两频道按 (taskId, 已投递最大 seq) 只投一次；
前端 **WS 优先 + 轮询兜底**（指数退避重连 1s→30s+jitter，断开自动恢复 3s 轮询）。

### 5.4 请求安全闸门
Content-Type 仅 `application/json`（否则 415）；body 上限 2MB（413，超限仍读完剩余数据以便客户端拿到错误）；
同源闸门（`Sec-Fetch-Site: cross-site` / Origin≠Host / `Origin: null` → 403，`AUTOTEST_ALLOW_CROSS_ORIGIN=1` 可关）；
模型端点限制见 §4。

## 6. 业务内核 vs 基础设施（重写取舍）

**必须保留的业务内核**（这些是"结果可信"的来源）：
1. 占位 + 终态守卫两把锁；lane 按库串行。

3. 三道质检顺序：确定性校验（控件引用/句式契约）→ 定向修复 → LLM 自审（增量合并）。

13. 无真机/无判据/LLM 不可用 → 一律失败并写明原因的三条"不模拟"纪律。
14. 问题归因闭环（证据可回查 + 人工验收 + 知识沉淀）。
