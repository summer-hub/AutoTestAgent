# AutoTestAgent 用例生成/优化 Agent 优化计划

> 2026-09-01 · 基于 executor.ts / uiExplorer.ts / llmHarness.ts / hypiumGen.ts 源码诊断

## 一、问题清单（根因定位）

### 数量不达标（explore_cases）

| # | 位置 | 根因 |
|---|------|------|
| N1 | `executor.ts` exploreCases 一次 LLM 调用 `maxTokens=4000` | 遍历 40 页要求"每页至少 1 条"，输出必截断，extractJson 只能打捞部分对象 |
| N2 | `executor.ts` sysCompact 重试降级 | 解析失败后重试只要求「4 条精简用例」，数量被代码压死 |
| N3 | `executor.ts` reviewAndRefine 整表替换 | 评审输出截断 → 残缺 revised 列表直接替换完整草稿，自审环节反而丢用例 |
| N4 | `executor.ts` insertDraftCases | `maxCasesPerTask=20` 硬截断，超出静默丢弃 |

### 质量不达标

| # | 位置 | 根因 |
|---|------|------|
| Q1 | executor.ts 全局 | 零确定性校验：控件引用 ∈ controls 清单只靠 prompt 自觉，LLM 审 LLM 是弱信号 |
| Q2 | `uiExplorer.ts` pageSignature | 只按文本集合去重，Tab 页/动态内容页误判"已访问"漏页 |
| Q3 | `executor.ts` optimizeCaseById | 不知道用例对应哪个页面，注入前 10 页全部控件清单，模型对不准；优化后 scriptStatus='未绑定' 却不重生成脚本 |
| Q4 | `executor.ts` → `hypiumGen.ts` | 生成端无步骤句式约束，stepToPython 正则只认固定句式，大量步骤落到"未映射步骤"注释行 |

### 链路追踪缺失

| # | 位置 | 根因 |
|---|------|------|
| T1 | `executor.ts` traceTask | tasks.trace JSON 列读改写，无并发保护；无 traceId/spanId 串联全链 |
| T2 | `executor.ts` AI 返回 trace | 只存前 600 字符，失败无法复现；LLM 调用无 token/延迟/重试记录 |
| T3 | `llmHarness.ts` lastLlmCall | 全局变量，并发任务互相污染模型记录 |
| T4 | `llmHarness.ts` llm-raw.json | 硬编码绝对路径落盘 |

## 二、改造计划

### P0 — 数量 + 质量止血（本轮实施，不动 DB schema）

1. **按页分片生成（map-reduce）**
   - exploreCases 中遍历页按 `agent.genPagesPerShard`（默认 2 页/片）分片，逐片独立调用 LLM；
   - 每片用例数按页面丰富度分配（controls>8 或 scrolls>0 → 2 条，否则 1 条）；
   - 单片失败只重试该片（同要求、严格 JSON 指令），不全局降级。
2. **删除 sysCompact「4 条精简」降级**
   - exploreCases / writeCases 的重试改为同要求重试（仅强化"只输出 JSON"指令）。
3. **reviewAndRefine 改增量合并**
   - 评审 Agent 只输出问题条目（带 1-based index），按 index 替换对应草稿；
   - JSON 解析失败或 revised 缺 index → 保留原稿，绝不整表替换。
4. **上限按页配额**
   - exploreCases 入库上限 = max(agent.maxCasesPerTask, 页数 × 每页配额)。
5. **用例溯源 pagePath**
   - 草稿携带 pagePath（来自该片页面），写入 case_versions.snapshot（零 schema 变更）。
6. **优化 Agent 定向上下文 + 自动重绑脚本**
   - optimizeCaseById 读取最新 version snapshot 的 pagePath → 只注入该页控件清单；
   - 优化落库后自动重新生成 Hypium 脚本并置 script_status='已绑定'。
7. **步骤句式契约**
   - 生成/优化 prompt 下发「步骤动词句式白名单」（与 stepToPython 正则一一对应）；
   - hypiumGen 输入步骤支持 `输入「内容」到「控件」` 二段式解析。
8. **轻量确定性校验（guardrail）+ 定向修复**
   - 点击/输入类步骤中「X」引用必须 ∈ 对应页 controls 清单（验证类步骤豁免；二段式输入只校验目标控件）；
   - 子串匹配要求控件文本 ≥2 字，避免单字符控件让 includes 恒真、校验形同虚设；
   - 违规用例**不直接丢弃**：连同该页真实控件清单回灌 LLM 重写一次（repairDrafts），复检通过则保留、仍不合格才丢弃并沉淀 lessons。

### P1 — harness 闭环

- ✅ **dry-run 闭环（执行器为真）**：生成 → 脚本 → 模拟器/真机真跑 → 失败证据回灌重写（2026-09-01 已落地，见实施记录）；
- pageSignature 增强结构指纹（控件层级/坐标分桶），减少 Tab/动态页误判漏页；
- agent_events 追加式事件表（task_id/span_id/parent_id/kind/tokens/latency_ms），LLM 调用层统一埋点；
- lastLlmCall 改为随调用返回值传递；llm-raw.json 落盘路径改 workspace 相对路径。

### P2 — 观测与规模化

- 全链 traceId 贯穿：任务 → LLM 调用 → 遍历 ops → 用例 → 脚本 → 执行结果；
- 结构化输出（JSON mode/schema）替代 extractJson 容错；
- 分片生成并发化（限流内）+ 失败分片自动补跑。

## 三、验收标准

- 数量：遍历 N 页 ≥ 生成 min(N×1, 配额) 条用例；单页富页面 ≥ 2 条；不再出现"全局只剩 4 条"；
- 质量：入库用例的点击/输入类步骤控件引用 100% ∈ 该页遍历 controls（程序校验）；优化后脚本自动重绑；
- 可回溯：每条 case_versions snapshot 含 pagePath；自审环节不再出现"修订后数量 < 修订前"。

  - 新增确定性自检 `scripts/verify-step-contract.mjs`（`npm run verify:contract`）：9 条句式映射 + 7 条 guardrail 判定，共 16 项全通过。不连 DB、不调 LLM，可在 CI 中作为契约回归门禁。
- 2026-09-01：dry-run 闭环落地（P1 核心项），新增 `services/dryRun.ts`，改动 `executor.ts`、`hdc.ts`、`settings.ts`。
  - `dryRunCase` 逐步执行并在**每个失败点抓取界面真实可见控件**，产出结构化 `failureBrief` 回灌 LLM；连续失败 N 步后停止（界面已偏离，后续证据不可信）。
  - `dryRunAndRepair` 在入库后对前 N 条用例真跑，失败用例经 `repairFromDryRun` 重写并升版本 + 重绑脚本；无设备时自动跳过，不阻断主流程。
  - 新增配置项：`agent.dryRunEnabled`(true) / `agent.dryRunMaxCases`(5) / `agent.dryRunPerStepTimeoutMs`(15000) / `agent.dryRunFailStreakStop`(2)。
  - 导出 `hdc.runStepWithTimeout` 供 dry-run 逐步执行（整批 `executeCaseSteps` 是黑盒，拿不到失败点界面证据）。
