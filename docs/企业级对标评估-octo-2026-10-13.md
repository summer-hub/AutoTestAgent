- 评估时间：2026-10-13

- 结论先行：**octo 是「企业 IM 平台原生长出的 agent 工作场所」，AutoTest 是「垂直测试平台」。两者的企业级不在同一个竞争面上——我们不需要成为 octo，但 octo 有 4 个具体机制值得抄（见 §4），且全部做得到。**

## 一、OCTO 是什么（实测定位）

「the open workplace built for humans × AI agents」——**人 × AI agent 的开放工作场所**。核心概念 **Lobster**：OpenClaw 驱动的「数字分身」（digital doubles），替人 thinking/doing。产品血缘：DMWork 企业 IM + WuKongIM IM 内核。

五仓库分工（单一后端 + 五端）：

| 仓库 | 形态 | 职责 |
|---|---|---|
| octo-server | **Go 1.25** 单体后端 | REST + WebSocket；Lobster agent 编排（路由/会话/工具调用是一等公民）；WuKongIM 控制面（IM 内核可换）；47 业务模块 + 60 基础设施包；模块 `register.AddModule` + 内嵌 SQL 自注册 |
| octo-web | pnpm monorepo（turbo） | apps/web + apps/extension（浏览器扩展）；packages 含 chat-core/chat-react、**dmworkmcp**、**dmworkskillmarket**（技能市场）、mail、file-preview |
| octo-cli | **Go 单二进制** | **专供 AI Agent Bot 通过 exec 调用的 REST 客户端**：metadata 驱动命令树、stdout 结构化 JSON envelope、stderr 确定性错误分类、无交互 I/O |
| octo-ios | Swift（Xcode） | WuKongIM SDK 模块化封装 + 推送（NotificationService） |
| octo-android | Kotlin（Gradle） | 同上 Android 侧 |

## 二、OCTO 的企业级配方（实测归纳，8 条）

1. **多租户 = Space 隔离**：所有访问用户数据的 handler 必须过 Space middleware；所有路由默认过 `AuthMiddleware`（跳过需在代码里写明理由）；bot 操作先验归属；thread 先验父频道权限。`.octospec/rules/space-isolation.md` 把这条固化成 **load_bearing 规则**。
2. **信任边界纪律**：入站适配器（GitHub/WeCom webhook、推送、语音）携带攻击者可控内容，转义决策必须做在「调用方跨不过去的边界」，且**同级适配器必须一致**（堵一个不能漏另一个）——`trust-boundary.md` 规则。
3. **身份体系**：OIDC/SSO（`modules/oidc` + `pkg/oidcboot` + aegis-oidc-migration 计划）；bot 身份供给（botfather/botidentity/bot_provision）；**令牌三级分类**：`app_*`（App Bot，禁搜索）/`bf_*`（User Bot 全量）/`uk_*`（真人 API key），CLI 本地按前缀 + 域规格 `x-octo-allowed-token-kinds` 前置校验（exit 2），服务端再兜底 FORBIDDEN。
4. **审计与运营**：`pkg/accesslog`（访问日志）、`modules/opanalytics/statistics/report`（运营分析）、`pkg/metrics`、`pkg/reqid`（请求 id 贯穿）。
5. **限流**：`pkg/ratelimit` 按 UID × 路由；同样固化为 load_bearing 规则。
6. **规格驱动开发（.octospec）**：规则带 frontmatter（`inject_when: paths/touches`、`load_bearing`、`priority`），**按代码触碰的路径/主题向 agent 上下文机器注入**；规则索引 `_index.yaml` 定义冲突解决（repo 覆盖 global、超预算按 load_bearing→priority 截断）。每个仓库都有 AGENTS.md + CLAUDE.md 给编码 agent 导航。
7. **Agent 友好的接口层**：octo-cli 是「给 agent 用的 CLI」的教科书——JSON envelope（含 `identity.source` 说明令牌来自哪个环境变量）、确定性错误分类、零交互；web 侧有 MCP 包与技能市场；服务端把 Lobster 当**一等会话参与者**（不是 bolt-on）。
8. **可换内核 + OOTB 部署**：WuKongIM 经薄控制面驱动（可替换）；`octo-deployment` 一键 Compose 栈（server+admin+web+matter+summary+IM+MySQL+Redis+MinIO+nginx）；灰度切换有 `cutover` 框架 + runbook。

## 四、差距分级与「能否做到」结论

### A. 已对等或我们有独有优势（不需要补）

- 认证/凭据/可观测/审批/治理：P0 轮次后**基本对等**，审批队列（一次性令牌）和技能供应链锁（哈希锁定）是我们的独有项；
- 测试文化：28 套离线自检 + 真实浏览器遍历 + 压测，octo 是 Go 单测 + e2e（`pilote2e`），我们在「UI 真实验证」上更强。

### C. 做不到/不该做（结构性差异，不是差距）

| 项 | 原因 |
|---|---|
| **Space 多租户** | octo 的根是「工作场所」（人+频道+空间）；AutoTest 的根是「测试执行平台」（库×用例×设备）。多租户需要把 library/设备/知识库全部按租户域重划——除非产品目标就是「多团队 SaaS」，否则是负资产（我们的部署形态是团队内网/单机）。**建议不做，用反向代理 + 多实例隔离替代。** |
| **iOS/Android 端** | 测试工程师在 PC 前干活（桌面端已覆盖），移动端只能是「查看执行状态」的附属价值；且需要原生团队与两端发版链路。**建议不做**；如确有需要，B4 的 WS + 只读 H5 一页即可覆盖 80% 诉求。 |
| **WuKongIM 级 IM 内核** | 我们的「消息」是任务轨迹与执行事件，不是人际通信。照搬 IM 是把简单问题复杂化。B4 已覆盖真实需求。 |
| **技能市场（web 侧）** | 我们的技能是测试方法论（5 个 SKILL.md + 供应链锁），受众是内部测试团队，不是生态分发。**保持本地锁定制**，不做市场。 |

## 六、总结论

**能做到，且大部分已经做到了。** octo 的真正护城河不是任何单项机制（它的每个机制我们都能实现或已有对等物），而是「**企业 IM 的血缘**」——Space/频道/IM 内核/五端这些是从母体衍生的，我们不该也不会去长出一个 IM。对我们真正有价值的翻译是：

> 把「119 路由的 REST API」包装成 **agent 原生的接口层**（CLI + MCP），把「CI 门禁」升级为 **编码时规则注入**，把「轮询」换成 **WS 实时**——三件事合计约 6-8 周，做完之后 AutoTest 在「agent 可驱动性」上与 octo 同代，而在「垂直测试执行 + 真实验证文化」上保持领先。

C 类（多租户/移动端/IM 内核/技能市场）明确不追——那是用我们的短处比别人的长处。
