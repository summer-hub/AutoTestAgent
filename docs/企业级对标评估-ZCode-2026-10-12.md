## 一、ZCode 企业级能力清单（8 维度，实测归纳）

| 2 | Agent 运行时 | `core` 含 agent loop / context / memory / **compact（上下文压缩）** / hooks / **permission（工具权限）** / mcp / model；工具调度有 parallelGroups + concurrentSafe + 取消信号 + turnControl；**profile 化 subagent 体系**，后台 subagent 完成经 `<task-notification>` 自动唤醒 main agent；**dynamic-workflow-runtime**：child-cell 隔离执行单元 + 流式协议；**rewind（会话回退）** |
| 3 | 工具与生态 | **插件体系** 15+（browser-use / android-emulator / ios-simulator / documents / pdf / spreadsheets / presentations / cua / plugin-creator / skill-creator / superpowers…）；MCP adapters；**skills-lock.json 供应链锁定**（source + skillPath + computedHash） |

## 二、AutoTest 现状（同 8 维度，如实自评）

| # | 维度 | 现状 | 评级 |
|---|---|---|---|
| 1 | 架构与治理 | 单包双入口 + web/shared/desktop/scripts 分工；**无 architecture-policy.yaml、无 ADR、无公共 API 契约层**；规范靠 README + 重度注释（「踩坑文化」其实是资产）；有 `docs/架构评审` 但一次性 | 🟡 部分 |
| 2 | Agent 运行时 | **taskLane 生命周期很硬**：同库串行/跨库并行、抢占锁、排队取消、abort 贯穿 LLM 与子进程、终态不被迟到结果覆盖；taskEvents seq/快照可重建；agent_bindings 四类绑定（builtin/prompt/skill/external）+ 全局/库级 scope；知识库 md-first 可解释检索 + 注入预算；**确定性上下文装配**（覆盖矩阵/用例计划/hypiumGen 是代码不是模型发挥）；LLM 跨模型重试 + token 闸门 + Redis 跨节点限流。**缺**：上下文压缩、会话回退、动态工作流、subagent 画像体系 | 🟡 部分（生命周期项 ★，运行时完整性 △） |
| 3 | 工具与生态 | 工具是**内建服务**（gitRepo/hdc/uiExplorer/hypiumRunner/apiExtract…），无插件 SDK、无第三方扩展路径；外部 agent 走 externalCmd；**skills/ 无版本锁定无哈希**（5 个技能，SKILL.md 标准格式但可被任意篡改） | 🟡 部分 |
| 4 | 可观测性 | agent_events（traceId/spanId/parentId + tokens + latency）、task 事件流、LLM 埋点——**库内闭环**；**无 OTLP/无 metrics 端点/无结构化日志**，接不进 Grafana/Prometheus/ELK | 🔴 缺失（出口） |
| 5 | 安全 | 同源闸门、密钥出参脱敏、模型端点安全校验（拒元数据地址）、路径穿越防护、2MB 体限；**api_key 明文入库**（仅出参打码）、**无工具级权限/审批**、**无 exec 沙箱**、**无账号体系**（打开即用是明确设计取舍） | 🔴 缺失（企业场景） |
| 6 | 测试与 CI | **22 套离线自检（1104 断言）+ 真实浏览器 UI 遍历器 + 压测脚本**——内部工具里属罕见强度；typecheck + lib 产物一致性 + tag 校验门禁。**缺**：coverage 门禁、容器化 E2E、affected-tests、架构审计即代码 | 🟢 强（单项冠军） |
| 7 | 多端交付 | DSH 插件 + 纯 Web 独立版 + Tauri 桌面端（三链路刚交付）；**无 TUI、无远程控制、无 i18n** | 🟡 部分 |
| 8 | 运维生产化 | MySQL 连接池、Redis、集群模式、优雅退出、归档、僵死清理、统计预聚合；**仅 /healthz，无 /metrics、无日志聚合** | 🟡 部分 |

## 三、差距清单与补齐路线

### P0——不补不进企业生产（估约 6-9 人周）→ ✅ 已全部补齐（2026-10-13，含 6 套新自检门禁）

| # | 差距 | 落地形态 | 自检 |
|---|---|---|---|
| P0-1 | **无认证/多租户/RBAC** | `services/auth.ts` + `api_keys` 表：Bearer Key（SHA-256 哈希存储、明文仅创建时一次）、admin/operator/viewer 三角色（GET=viewer / 写=operator / 配置·模型·Key 管理=admin）、回环豁免（桌面端/本地开发零感知）、Web 登录门 + 设置页 Key 管理区 | `verify:auth` 29 项 |
| P0-2 | **凭据明文存储** | `services/crypto.ts`：AES-256-GCM 信封加密，master key 取 `AUTOTEST_MASTER_KEY` 或数据目录 `.master-key`（自动生成 + POSIX 0600 / Windows icacls ACL 收敛）；models.api_key 与 settings 敏感键落库即密文，旧明文懒迁移，出参仍掩码 | `verify:crypto` 21 项 |
| P0-3 | **无可观测出口** | `GET /api/autotest/metrics` Prometheus 文本格式（HTTP 按路由计数/延迟直方图、LLM 调用/token/失败、任务 lane 深度/事件、uptime；认证开启时限 admin）；`AUTOTEST_LOG_FORMAT=json` 结构化请求日志 | `verify:metrics` 27 项 |
| P0-4 | **无工具级权限/审批** | `services/approvals.ts` + `approvals` 表：`exec.autoApprove=false` 后危险操作（拉取/更新仓库、生成/删除脚本、删库/删用例/删任务）入队；**一次性批准令牌**机制（批准→发起方重试同一操作即放行）；人工队列页审批区（operator+ 决策） | `verify:approvals` 27 项 |

**共同设计原则**：四项均默认关闭/兼容（`auth.enabled=false`、autoApprove=true、指标常开但零成本、加密自动生效但旧数据透传）——企业部署显式开启，DSH 插件形态与既有独立版行为不变，28 套自检全绿（1236 断言）。

### P1——企业级体验分水岭（估约 8-12 人周）→ 🟡 2/6 已落地，4 项遗留（见下）

| # | 差距 | 状态 |
|---|---|---|
| P1-1 | 架构治理缺位 | ✅ **已落地**：`autotest/architecture-policy.yaml`（模块/owner/layers/例外）+ `scripts/audit-architecture.mjs` 机器门禁（DSH 解耦白名单、shared 仅类型、web/desktop 隔离、分层顺序、YAML↔脚本双边防漂移），接入 `verify:architecture`（8 项断言，反向验证过门禁有牙齿） |
| P1-2 | 技能供应链无锁定 | ✅ **已落地**：`skills/skills-lock.json`（5 技能 29 文件逐枚 SHA-256 + 合并 digest）+ `services/skillLock.ts` 启动校验 + `GET /skills` 状态面 + `skills.lockEnforce` 强执模式；桌面端随包分发自带锁；`verify:skill-lock` 18 项断言 |

| P1-4 | exec 无沙箱 | ⬜ 遗留（理由见下） |
| P1-5 | 无插件化运行时 | ⬜ 遗留（理由见下） |
| P1-6 | CI 缺门禁 | 🟡 **部分**：新增 6 套自检门禁 + 架构审计 + 浏览器 UI 遍历器已接入；coverage 门禁 / affected-tests / 容器化 E2E 遗留 |

### 遗留项及理由（诚实记账）

| 项 | 为什么遗留 | 建议时机 |
|---|---|---|
| P1-3 上下文压缩 / 会话回退 | taskEvents 快照机制是现成地基，但 compact 需要设计「摘要哪些字段不丢判据」，rewind 需要定义副作用（已下发的脚本/已跑的计划）的补偿语义——两者都要产品决策，不适合闭门造车 | 与「长任务体验」需求一起做 |
| P1-4 exec 沙箱 | 桌面端已有 Job Object 经验可移植；但服务端主要跑 Linux，namespace/seccomp 方案要按发行版逐一定稳，且 git/hdc/python 是测试本职（沙箱化可能破坏真机链路）——正确姿势是先定义「哪些 exec 需要隔离」再实施 | 有多租户远行需求时 |
| P1-5 插件化运行时 | 工具服务抽象成 plugin 契约是大改（manifest + 生命周期 + 权限声明）；当前 externalCmd + agent_bindings 已覆盖「外部 agent」场景，进程内插件化收益主要在生态开放，非当前痛点 | 有第三方扩展诉求时 |
| P1-6 剩余 CI 门禁 | coverage 门禁需要先定基线阈值（当前 1236 断言是离线自检，非单测覆盖率，口径不同）；容器化 E2E 需要桌面 GUI 环境（WebView2 + 显示服务器），CI 镜像成本高 | 下一轮工程迭代 |
| P2（TUI/远程控制/i18n/web-share） |  polish 项，无企业阻塞 | 按用户诉求排期 |

### P2—— polish（按需）

TUI（tokens/成本看板）、web 远程控制桌面端、i18n、web-share 只读分享、死码检测（knip 类）。

## 四、总结论

**P0 硬门槛已全部补齐（2026-10-13）**：认证多租户、凭据加密、可观测出口、工具权限审批四项落地，均遵循「默认兼容、企业显式开启」原则——DSH 插件形态与既有独立版部署行为不变（28 套自检 1236 断言全绿为证）。另完成两个高性价比 P1：架构治理即代码（`architecture-policy.yaml` + CI 门禁）与技能供应链锁（`skills-lock.json` + 启动校验 + 桌面端随包分发）。

**当前定位**：「企业就绪的内部平台」——四人 P0 缺口（单机自用无所谓、多人共用即出事的那条分界线）已经抹平；剩余 P1-3/4/5/6 与 P2 属「体验与生态」层，不构成企业部署阻塞（理由见遗留项表）。

**验证证据**（2026-10-13 三链路全测）：`verify:all` 1236 PASS / 0 FAIL / 28 套；Web 端 17 页真实浏览器遍历 17/17 + 认证 UI 探针 13/13（登录门→Key 登录→Key 管理→审批区→错误 Key 掉线）；DSH 插件形态冒烟 7/7；桌面端 WebView2 窗口遍历 17/17 + 硬杀防孤儿实测通过；压测 21.5K RPS / P99 17ms / 0 错误（新增中间件未损吞吐）。
